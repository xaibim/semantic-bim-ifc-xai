# Planned Dataset Governance, Split and Leakage Protocol

STATUS = PLANNED_NOT_EXECUTED
CURRENT_SAMPLE20_SCOPE = MINIMAL_PUBLIC_FIXTURE_ONLY

## 1. Scope Boundary

This protocol defines the future dataset governance controls for the planned
benchmark. It does not modify the public schema and it does not reclassify
`sample20` beyond its current minimal public fixture scope.

## 2. Record Identity and Lineage

Future methodological fields include:

- `record_id`;
- `root_case_id`;
- `variant_id`;
- `source_record_id`;
- source category;
- source licence or permission state;
- creation method;
- transformation history;
- reviewer state;
- schema version;
- lineage hash.

The current public schema is unchanged.

## 3. Root-Case Grouping

- All variants derived from the same case must share `root_case_id`.
- No `root_case_id` may cross train, validation, test or evaluation splits.
- Translations, paraphrases, complexity changes and derived expected negatives
  remain in the same group.
- Splits must be generated by groups, not by individual records.

## 4. Duplicate Detection

Duplicate control has three layers:

1. exact byte/content hash;
2. normalized exact duplicate;
3. semantic or near duplicate.

Rules:

- normalization and thresholds must be frozen before split construction;
- all matches and decisions must remain in an audit log;
- manual review of ambiguous matches must be documented;
- deduplication is not complete leakage control.

## 5. Split Construction

The split protocol requires:

- a split manifest;
- hashes for each split;
- counts by root case and by record;
- documented stratification;
- test and evaluation locked before model selection;
- no correction based on final results may return to the training set without a
  new dataset version.

## 6. Retrieval-Corpus Leakage

Leakage must be separated across:

- records;
- splits;
- retrieval corpus;
- few-shot examples;
- prompts or tools;
- evaluation targets or answers.

The retrieval corpus must have its own version and hash.

An evaluation document must not be available to a method's retriever when that
availability would directly reveal the evaluated target.

## 7. Model-Contamination Disclosure

- Absence of contamination in pre-trained models cannot always be proven.
- Model identifier, revision and availability date must be recorded.
- Limits of knowledge about pretraining data must be declared.
- This uncertainty must not be described as contamination-free.

## 8. Reference and Evidence Levels

E0 — TRACE_PRESENT

E1 — REFERENCE_RESOLVABLE

E2 — CLAIM_SUPPORTED

E3 — PROFESSIONALLY_SUFFICIENT

Rules:

- `sample20` demonstrates E0 only.
- E1 requires a resolvable identifier or location.
- E2 requires source-to-claim review.
- E3 requires documented professional judgment.
- E1, E2 and E3 belong to the future evaluated dataset.

## 9. Privacy, Licensing and Sanitization

The governance protocol includes:

- NER-assisted sanitization;
- manual privacy review;
- project-name, person, path and location review;
- licence or permission state;
- exclusion of records with unresolved publication rights;
- no publication of private data, adapters, checkpoints or restricted logs.

## 10. Professional Review and Adjudication

The future workflow must include:

- reviewer eligibility;
- independent review where feasible;
- disagreement state;
- adjudication record;
- no silent modification;
- reviewer version and date;
- separation between schema compatibility and professional sufficiency.

## 11. Freeze Manifest and Hashes

The frozen manifest should capture:

- dataset version;
- dataset content hash;
- split hashes;
- root-case grouping manifest;
- retrieval-corpus version and hash;
- model identifiers and revisions used for evaluation;
- metric implementation version;
- professional-review protocol version.

All values are `TO_BE_FROZEN` until the future protocol is executed.

## 12. Current Public Limitations

The current public artifact remains a minimal reproducibility fixture. It does
not establish future split validity, leakage absence, resolvable references or
professional sufficiency.
